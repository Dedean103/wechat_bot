# 小红书系统化调研

## 总原则

使用小红书 MCP 工具完成检索，不用网页搜索、Playwright 或其他方式替代。先验证 MCP 与登录状态；未登录时停止调研并引导 `/xhs-login`。所有价格标为“作者/评论自报”或“估算区间”，不得伪装成实时采购报价。

## 标准链路

### 1. 验证连接和登录

1. 确认 `mcp__xiaohongshu_mcp__check_login_status` 可用。
2. 调用 `check_login_status({})`。
3. 已登录才继续；未登录时提示使用 `/xhs-login`，扫码完成后再次调用 `check_login_status`，不要用其他渠道替代。
4. 记录本次调研的登录状态，但不要输出 cookie、token 或二维码数据。

### 2. 设计搜索矩阵

根据主题生成 3–6 组互补关键词，至少覆盖：

- 核心方案：`主题 + DIY`、`主题 + 教程`；
- 配置与价格：`主题 + 配件/价格/预算`；
- 对比项：用户关心的品牌、材料、规格或技术路线；
- 风险：`主题 + 避坑/翻车/后悔/售后`。

调用 `mcp__xiaohongshu_mcp__search_feeds` 搜索。记录每组关键词、返回数量和候选笔记的标题、feed_id、点赞、评论、收藏。为每篇入选笔记生成参考链接：`https://www.xiaohongshu.com/explore/{feed_id}`。如果工具返回了官方笔记 URL，优先使用返回的 URL；如果只返回 feed_id，就使用上述 canonical URL，并注明访问可能需要登录。后续详情调用所需的 `xsec_token` 只用于工具参数，不在报告中公开，也不把 token 拼进公开链接。

### 3. 筛选笔记

不要只选点赞最高的帖子。建立“高热度 + 高相关 + 反例/风险”的组合：

- 高热度样本：优先选择互动明显靠前的笔记，作为主流方案样本；
- 高相关样本：即使点赞较低，只要有明确价格、材料、尺寸、部件或施工细节，也纳入；
- 风险样本：纳入翻车、避雷、售后和长期使用反馈；
- 去重：同一作者、同一方案的重复笔记只保留信息最完整的一篇。

通常先从每组搜索结果中保留约 8–15 个候选，再对去重后的约 6–12 篇调用详情。报告中说明实际搜索组数、候选数和详情样本数，不虚构统计量。

### 4. 读取详情和评论

对重点笔记调用 `mcp__xiaohongshu_mcp__get_feed_detail`，传入搜索结果中的 `feed_id` 和 `xsec_token`。默认请求 `load_all_comments=true`，设置合理的 `limit`（通常 20–50）；若服务或笔记过大，说明实际读取上限。

从正文和评论中分别提取：

- 方案结构、尺寸、材料和品牌；
- 电机/核心部件类型、数量、规格；
- 明示价格、漏算项和评论中的重新估算；
- 安装步骤、工具、加工和运输要求；
- 使用反馈、故障、稳定性、噪声、变形和售后。

评论处理规则：

1. 保留原作者回复，因为它可以确认或反驳评论中的疑问；
2. 将评论归类为价格真实性、部件配置、安装难度、稳定性/耐久、材料质量、售后和安全风险；
3. 同一问题的重复评论合并为一个趋势，不把重复提问当成多个独立证据；
4. 区分“作者确认”“用户质疑”“用户自报经历”和“无法验证的猜测”；
5. 负面评论不自动等于事实，只有作者回复、多个独立用户重复反馈或正文证据支持时，才写成较强结论；
6. 不做未经数据支持的好评率、差评率或统计显著性结论。

### 5. 形成分析表

先在内部建立一行一个方案的矩阵：

| 方案 | 关键配置 | 明示成本 | 评论修正成本 | 证据强度 | 主要短板 |
|---|---|---:|---:|---|---|

“证据强度”使用高/中/低：正文有完整清单且评论相互印证为高；正文部分明确、评论有补充为中；只有标题或单条评论为低。价格冲突时同时保留作者口径和评论口径，并解释差异。

### 6. 生成结论

先给一句可执行结论，再给比较表。结论必须区分：

- 直接来自笔记正文的事实；
- 评论归纳出的常见问题；
- 基于多个案例的工程/消费建议（明确标注为综合判断）。

推荐至少输出 2–4 个方案档位，并回答用户指定的比较项。例如升降桌调研要明确说明单/双电机、桌板材质、部件、预算和短板，而不是只复述笔记标题。

## 固定报告格式

使用中文，按以下顺序输出：

1. **结论先行**：推荐档位、适用人群和大致预算；
2. **调研范围**：关键词组数、候选笔记数、详情笔记数、评论读取口径；
3. **方案对比表**：配置、预算、适用场景、证据强度；
4. **部件/材料拆解**：把总价拆成核心部件、加工、辅料和可能漏项；
5. **评论中的潜在短板**：逐方案列出问题、证据类型和严重程度；
6. **综合建议**：给出推荐方案、妥协点和购买/制作前检查清单；
7. **局限性**：说明价格为自报或估算、样本不是全站统计、未验证的链接或评论不确定性。
8. **参考笔记**：按方案列出标题、作者、互动量和可点击的小红书链接；同一笔记只列一次。

方案表建议使用：

| 方案 | 配置 | 预算 | 优点 | 评论暴露的短板 | 建议 |
|---|---|---:|---|---|---|

不要公开 `xsec_token`、cookie、登录凭据或完整内部工具响应。可以公开笔记标题、作者昵称、互动量和 feed_id（如有助于用户复核），但不把互动量误当成质量证明。

参考链接格式：

`[笔记标题](https://www.xiaohongshu.com/explore/{feed_id})`

链接只作为来源定位，不代表内容经过小红书官方或第三方验证；若链接打不开，保留标题和 feed_id，并说明需要在小红书 App 内登录查看。

## 失败和边界处理

- MCP 工具不可用：提示 `/setup-xhs-mcp`，不要切换到其他抓取工具；
- 未登录：提示 `/xhs-login`，不要继续搜索；
- 搜索结果不足：扩展同义词和风险词，并说明样本不足；
- 详情或评论加载失败：记录失败笔记，不用标题推断正文；
- 价格只有宣传口径：标记为低证据，并寻找评论中的反向估算；
- 用户要求购买、联系商家或发布内容：先把调研结论和拟执行内容展示给用户，等待确认。
